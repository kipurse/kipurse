# 资金转移分析（FinCEN + 德州）

> **不是法律意见。** 这是为咨询律师准备的信息摘要。下面的事实描述的是 2026-11-03 时已建成的产品。

## 1. 分析所依据的产品事实
- **非托管：** 每个用户有一个自己的智能钱包（以 Coinbase Smart Wallet / Base Account 为所有者）。启付没有资金池，从不持有用户的 USDC 或私钥。
- **服务器权限：** 服务器持有 executor/session key，只能在用户链上签好的 SpendPermission 额度内、按用户规则付款；不能添加新收款人（需要手机 Face ID 签名）、不能改额度、不能阻止提现。
- **提现：** 只能回到用户自己的 Coinbase 钱包；服务器宕机时也能用开源页面提现。
- **费用：** 每笔付款 0.1% 服务费（USDC，从用户钱包余额扣），网络费按实际成本从用户钱包余额扣。新用户开户的网络费固定为 0.05 USDC（「开户费」），同样从钱包余额扣除。
- **充值：** 只从用户自己的 Coinbase Wallet / Base Account 转入；Apple Pay 购买由 Coinbase Onramp 完成（Coinbase 是持牌 MSB）。
- **身份：** 只依赖 Coinbase Verified Account 链上证明；启付自己不做 KYC。
- **公司：** Blessbridge Global Trading LLC（德州休斯顿）。

## 2. FinCEN（联邦）
- 2019 年 FinCEN 指引（FIN-2019-G001）§4.2：**非托管钱包软件提供者**（不持有、不控制用户资金）一般**不是**资金转移商。关键在于「是否独立控制价值」。
- 风险点（需要律师判断）：
  1. 服务器 executor key 能在额度内**主动**发起付款 —— 是否构成对资金的「完全独立控制」？我们的论点：额度和收款人范围由用户链上签名限定，用户可以随时撤销 / 暂停 / 提现，因此不是独立控制。
  2. 0.1% 费用从付款中收取 —— 是否让启付成为「接收并转移」链条中的一方？
  3. 开户网络费在开户时产生、之后从钱包余额扣除 —— 是否构成「为他人转移价值」或信贷？
  4. 手续费地址是启付的运营账户：收的是自己的费用，不是代客转账（需确认）。
- 如果被认定为 MSB：需要在 FinCEN 注册（Form 107）、建立反洗钱计划、提交 SAR/CTR、遵守 OFAC 合规。

## 3. 德州（州）
- 德州《金融法》第 152 章（资金服务业务），2023 年修订后明确把「虚拟货币」纳入「货币或货币价值」（HB 1666 / 2023），由德州银行厅监管。
- 德州银行厅监管备忘录 1037（虚拟货币）：非托管、不接收用户资金的软件通常不需要牌照；但「接收资金并承诺转移」的需要。
- USDC 是稳定币 → 在德州被视为「货币或货币价值」的可能性很高。
- 需要律师确认：启付的 executor 付款是否算「接收」用户的货币价值。

## 4. 其他州
- 用户不只在德州：纽约 BitLicense、加州 DFAL（2026 年 7 月起生效的牌照要求）对「控制」的定义可能更宽。建议律师给出 50 州矩阵，或限制上线的州。

## 5. 给律师的问题
1. 按 FIN-2019-G001，一个能在用户签名额度内主动付款的服务器 key，是否让我们成为资金转移商？如果是，怎样改架构可以避免（例如每笔都要用户签名）？
2. 0.1% 服务费从付款中扣除的方式，有没有监管影响？改成单独收费是否更好？
3. 开户网络费先产生、再从钱包余额扣除，是否构成借贷或资金转移？
4. 德州第 152 章 + 备忘录 1037：我们需要德州 MSB 牌照吗？是否需要书面向德州银行厅申请不采取行动函 / 确认？
5. 加州 DFAL、纽约 BitLicense：是否需要牌照，还是应该暂不向这些州开放？
6. 只依赖 Coinbase Verified 证明、不自己做 KYC，是否足够（尤其如果被认定为 MSB）？
7. OFAC 筛查（地址名单 + Chainalysis 链上预言机）是否足够？需要书面的制裁合规政策吗？
8. App Store 上架主体（Blessbridge Global Trading LLC）和服务条款中的责任限制、仲裁条款是否可执行？
9. 开源许可（Apache-2.0 + AGPL-3.0）对责任有没有影响？
10. 用户的 AI 代理在额度内付款，法律上算谁授权？条款需要怎么写？
